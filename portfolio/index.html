경기 상세 조회부터 점수와 전후 비교에 쓰이는 표본까지

항목직면한 문제해결과 결과
조회 대기와
중복 호출		경기 상세를 차례로 불러오면 대기 시간이 누적됩니다. 최근 경기 분석과 추이를 따로 수집하면 겹치는 경기를 다시 요청하게 됩니다.모드별 최대 59경기를 두 화면에서 재사용합니다. 상세는 요청당 4개씩 조회하고, 전체 작업자 8개와 요청 간격 제한을 적용했습니다.
조회 실패와
경기 순서		동시에 요청하면 경기 목록과 응답 순서가 달라질 수 있습니다. 일부 경기가 누락되면 분석 표본도 달라집니다.작업자별 HTTP 세션을 분리하고 원래 순서로 결과를 맞춥니다. 실패하면 후속 묶음 조회를 멈추고 부분 분석은 저장 대상에서 제외합니다.
점수 표본의
신뢰도		시도가 적으면 한 번의 성공·실패로 점수가 크게 움직입니다. 중단 경기의 득실점은 정상 종료 경기와 비교하기 어렵습니다.최소 5경기, 비율 지표는 최소 20회 시도 조건을 적용했습니다. 득실점·파울 등 일부 지표는 정상 종료 경기로 계산합니다.

기준 경기로 비교 구간을 나누다

추이 그래프의 이동 집계를 그대로 비교하면 변경 전 기록이 변경 후 수치에도 섞입니다. 전술을 바꾼 첫 경기를 기준으로 경기별 원본 기록을 나눠 각각 계산합니다.

화면의 변경 전 구간은 19경기지만 팀 득점은 17경기가 집계됐습니다. 지표마다 실제로 사용한 경기 수를 함께 표시합니다.

서버리스 환경의 저장과 캐시

SQLite로 분석 스냅샷과 로컬 실행을 구성했습니다. Vercel의 인스턴스 사이에서 공유해야 하는 캐시와 중복 요청 제어에는 Redis를 사용했습니다.

왜 HCX-005와 GPT-4o mini를 함께 썼는가

한국어 대화의 맥락을 유지하면서, 영어 상품 데이터에 맞는 검색 입력을 생성하는 Dual-LLM 구조

모델 / 코드 지정맡긴 작업특성과 선택의 연결
GPT-4o mini
gpt-4o-mini		한국어 세션 요약에서 영문 검색어 user_query와 품목명 query_category 추출영어 상품 데이터에 맞춘 변환 작업에 배정. 비용·응답 속도와 OpenAI API 연동 편의성을 고려해 검색어·품목명 추출로 역할을 한정
HyperCLOVA X
HCX-005		한국어 대화·맥락 갱신, 정보 충분성 판단, 후보 선택과 추천 설명NAVER HyperCLOVA X의 HCX-005 버전. 한국어·문화적 맥락을 다루는 대화에 활용. 이미지도 지원하지만 프로젝트에서는 텍스트만 사용

temperature=0으로 형식이 일관된 응답을 유도했습니다. 검색 조건과 추천 설명을 완성할 여유를 두고 긴 출력을 제한하기 위해 max_tokens=4096을 출력 상한으로 설정했습니다. 비용은 실제 생성한 토큰 수에 따라 달라집니다.

문제 정의와 서비스 구성

당시 팀은 감정에 공감하는 챗봇에서 한 걸음 더 나아가, 사용자의 상황을 파악하고 상담 기법에 따라 질문을 이어갈 AI 도구가 필요하다고 봤습니다. 상담형 챗봇과 고민을 나누는 익명 커뮤니티를 함께 만들었고, 반복 호출의 비용과 응답 속도를 고려해 GPT-4o mini를 사용했습니다.
